1. Executive Summary & What We Built

In this project, we built a fully autonomous Continuous Integration and Continuous Deployment (CI/CD) pipeline for a Node.js web application:

  • Zero-Dependency Core App: Arithmetic module (src/math.js) and CLI script (src/index.js).
  • Native Automated Tests: Tests verifying regular and edge-case behavior (test/math.test.js) using Node's built-in node:test runner.
  • Production Build Script: Compiles static assets and injects build metadata into dist/ (scripts/build.js).
  • Live Frontend Dashboard: Interactive web calculator and deployment status widget (public/index.html).
  • 3-Stage CI/CD Pipeline: Configured in .github/workflows/ci.yml to run Test (CI) ➔ Build ➔ Deploy (CD) on every commit and PR.

2. Step-by-Step Evolution of the Project

Phase 1: Project Foundation & Code Creation

Created the math module with error handling for division by zero and created 5 unit tests utilizing Node 18+'s native assertion library.

Phase 2: First GitHub Actions Workflow

Added .github/workflows/ci.yml configured with a parallel matrix across Node versions 18, 20, and 22 on Ubuntu virtual machines.

Phase 3: Comprehensive Reference Documentation

Authored in-depth guides in both Markdown and responsive HTML format (docs/github-actions-guide.html) covering GitHub Actions terminology, syntax, and security rules.

Phase 4: Adding Continuous Deployment (CD)

Implemented a frontend dashboard in public/index.html, a build script in scripts/build.js, and extended the workflow to deploy to GitHub Pages automatically.

Phase 5: Cross-Platform Linux Shell Bug & Resolution

Bug Encountered: In package.json, the test command was written as node --test test/**/*.test.js. While Windows PowerShell tolerated this glob, Ubuntu Linux non-interactive /bin/sh does not support recursive globbing without subdirectories, causing the test runner to fail.
Safety Guardrail Verified: GitHub Actions correctly refused to run the build and deploy jobs when the test failed!
Fix: Switched command to node --test, which leverages Node's built-in cross-platform test discovery. All jobs turned green, and the site deployed successfully.

4. How Any User Can Test This on Their PC

Anyone can clone and test this repository on their personal computer with zero configuration:

Step 1: Clone the Repository

git clone https://github.com/sumitkrgupta05/Learning-Gtihub-Action.git
cd Learning-Gtihub-Action

Step 2: Run Unit Tests

npm test

Step 3: Run the CLI Entry Point

npm start

Step 4: Generate the Production Build

npm run build

Step 5: View the Web App

Double-click dist/index.html (or public/index.html) to open it in your browser.

5. Manual Testing Workflows

A. Manual Run from the GitHub UI

  1. Visit the Actions Tab.
  2. Click "CI/CD Pipeline" on the left sidebar.
  3. Click the "Run workflow" dropdown button on the right.
  4. Select branch main and click "Run workflow".

B. Testing Failure Prevention

  1. Open test/math.test.js and change an expected value to an incorrect number.
  2. Commit and push to a child branch.
  3. Open a Pull Request on GitHub.
  4. Notice how GitHub Actions flags the PR with a red cross ❌ and blocks deployment.
